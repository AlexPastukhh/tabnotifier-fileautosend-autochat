# Fortis Notifier 5.7.32 — полный запрос внутри TXT (candidate)

Статус: CANDIDATE. Установленный Tampermonkey, Viewer, Docker, G2 и оба Repo-туннеля не изменены.

## Поведение
- TXT теперь содержит точный оригинал, полный Fortis task context и выбранные промпт/модули Planning Helper.
- Нативный ChatGPT composer содержит только короткую ссылку на TXT с правильным task_id, conversation_id и reporting_session_id (если есть).
- Оригинал сохраняется отдельно в GM для архива Observatory. Весь подготовленный файл в GM второй раз не дублируется.
- Notifier «Файл»: подготовить файл и короткий draft, без Send.
- Notifier ➤: большой суммарный текст (включая модули) — через файл + проверенный одиночный Send, небольшой текст — прежний native path.
- Observatory «Файл»: тот же полный файл, без Send.
- Observatory «Отправить»: всегда полный файл, одна попытка прикрепления; только при подтверждённой карточке и task_id — одиночный native Send.
- Observatory «Вставить»: остаётся обычной вставкой без Send. Для тяжёлых модулей использовать «Файл».

## Безопасность
- Не заменять уже занятый штатный редактор при автоматической отправке.
- Без подтверждённой карточки вложения либо точного короткого черновика автоматического Send нет.
- На неопределённой загрузке никаких повторов: один файл может уже существовать.
- send_initiated — не подтверждение приёма ChatGPT. Проверить историю перед любой повторной попыткой.
- Тесты исходников: 287/287 JS PASS, build:check PASS.
- Реальная проверка в Edge, PowerShell, Tampermonkey и архивном приёме ещё не выполнена.
- ChatGPT может иначе интерпретировать прикреплённый TXT по сравнению с введённым текстом.
